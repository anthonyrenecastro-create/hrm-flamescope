## Leveled verdict

- **Sound as a research/demo platform:** clean typecheck, full test suite
  green, deterministic and reproducible, ledger identity and leakage /
  causality boundaries genuinely enforced by tests, honest in-code
  labeling that simulated benchmarks are *not* real-world validation.
- **Not validated as a superior forecaster.** The 91.6% MAE advantage is
  on the engine's own simulated dynamics. Out-of-distribution (test B)
  it loses to plain persistence by ~1.9x on MAE and misses every
  incident. Any future claim needs test B (or held-out real telemetry
  via `runOutOfSampleTelemetryBenchmark`) to move, not test A.
- No real-telemetry benchmark was run — no held-out dataset exists in
  the bundle; that lane is untested at baseline, not failed.

## Baseline risks / open items (observed, not fixed)

1. **`npm install` is broken** (esbuild pin vs vite 8 peer). Fix is a
   one-line bump of the esbuild devDependency to `^0.28.0`; held for
   Zebulon's word since this pass was baseline-only.
2. **Telemetry auth is opt-in.** `server.ts` `telemetryAuthGuard` passes
   every request through when `TELEMETRY_API_KEY` is unset (verified
   live: unauthenticated OTLP POST → 202). Any deployment must set it;
   rate limiting still applies either way.
3. **Version naming drift:** metadata/README say 4.0, UI/types/tests
   say 4.1. Cosmetic, but worth unifying before any public surface.
4. **ZIP-only repo** — no browsable source, no CI. Extracting to the
   repo root (as with prior HRMIT/IFT rescues) is a separate decision.
5. Runtime cost asymmetry: HRM 4.1 forecast is ~350–460x the runtime of
   persistence in test A (~21–28 ms vs 0.06 ms) — fine at this scale,
   relevant if node count grows.
